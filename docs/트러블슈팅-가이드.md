### 1. ❌ **javax.validation → jakarta.validation 마이그레이션**

**문제:** Spring Boot 3에서 javax.validation 패키지 사용 불가
```bash
package javax.validation does not exist
cannot find symbol class Validator
```

**해결책:**
```java
// Before (오류)
import javax.validation.ConstraintViolation;
import javax.validation.Validator;

// After (수정)
import jakarta.validation.ConstraintViolation;
import jakarta.validation.Validator;
```

**위치:** `ValidateRequestAspect.java:10-11`

### 2. ❌ **IdempotentAspect 제네릭 타입 오류**

**문제:** IdempotentOperation 제네릭 타입 불일치
```bash
method processRequest cannot be applied to given types
inference variable T has incompatible bounds
```

**해결책:**
```java
// Before (오류)
IdempotencyService.IdempotencyResult<?> result = idempotencyService.processRequest(
    idempotencyKey,
    () -> joinPoint.proceed(), // Lambda는 IdempotentOperation<T>가 아님
    responseType
);

// After (수정)
@SuppressWarnings("unchecked")
IdempotencyService.IdempotencyResult<Object> result = idempotencyService.processRequest(
    idempotencyKey,
    new IdempotentOperation<Object>() {
        @Override
        public Object execute() throws Exception {
            try {
                return joinPoint.proceed();
            } catch (Throwable e) {
                if (e instanceof Exception) {
                    throw (Exception) e;
                }
                throw new RuntimeException("Method execution failed", e);
            }
        }
    },
    (Class<Object>) responseType
);
```

**추가된 Import:**
```java
import com.popcorn.demo.common.cache.IdempotentOperation;
```

### 3. ❌ **테스트 생성자 매개변수 불일치**

**문제:** 컨트롤러/이벤트핸들러 생성자 매개변수 변경 후 테스트 실패

#### 3.1 OrderCommandController 생성자 오류
```bash
required: OrderCommandService,OrderDomainService,OrderRepository,OrderPaymentFacade,UserAddressRepository,ObjectMapper,TossPaymentsProperties,PaymentTokenService
found: OrderCommandService,OrderPaymentFacade,UserAddressRepository,ObjectMapper,TossPaymentsProperties,PaymentTokenService
```

**해결책:**
```java
// Before (누락된 매개변수)
OrderCommandController controller = new OrderCommandController(
    orderCommandService, orderPaymentFacade, userAddressRepository,
    objectMapper, tossPaymentsProperties, paymentTokenService);

// After (완전한 매개변수)
OrderCommandController controller = new OrderCommandController(
    orderCommandService, orderDomainService, orderRepository,
    orderPaymentFacade, userAddressRepository, objectMapper,
    tossPaymentsProperties, paymentTokenService);
```

#### 3.2 OrderEventHandler 생성자 오류
```bash
required: OrderQueryService,OrderNotificationService,OrderEventStore,OrderEventMetrics,TossPaymentService,ApplicationEventPublisher,JpaPaymentRepository,ObjectMapper
found: OrderQueryService,OrderNotificationService,OrderEventStore,OrderEventMetrics
```

**해결책:**
```java
// Before (4개 매개변수)
OrderEventHandler handler = new OrderEventHandler(
    orderQueryService, notificationService, eventStore, metrics);

// After (8개 매개변수)
OrderEventHandler handler = new OrderEventHandler(
    orderQueryService, notificationService, eventStore, metrics,
    tossPaymentService, eventPublisher, paymentRepository, objectMapper);
```

#### 3.3 PaymentEventHandler 생성자 오류
```bash
required: InventoryService,QrCodeService,JpaOrderItemRepository,PaymentCancelFailureService
found: InventoryService,QrCodeService,JpaOrderItemRepository
```

**해결책:**
```java
// Before (3개 매개변수)
PaymentEventHandler handler = new PaymentEventHandler(
    inventoryService, qrCodeService, orderItemRepository);

// After (4개 매개변수) - 일괄 변경 적용
PaymentEventHandler handler = new PaymentEventHandler(
    inventoryService, qrCodeService, orderItemRepository, paymentCancelFailureService);
```

### 4. ❌ **@Slf4j 누락으로 인한 log 변수 오류**

**문제:** 테스트 클래스에서 log 변수 사용 불가
```bash
cannot find symbol variable log
```

**해결책:**
```java
// Before (오류)
class AspectUnitTest {
    @Test
    void testMethod() {
        log.info("테스트 실행"); // 오류 발생
    }
}

// After (수정)
@Slf4j
class AspectUnitTest {
    @Test
    void testMethod() {
        log.info("테스트 실행"); // 정상 작동
    }
}
```

**적용된 파일:**
- `AspectUnitTest.java`
- `PerformanceTest.java`

## ⚠️ 주의사항

### 1. 어노테이션 순서
```java
// ❌ 잘못된 순서 (RateLimit가 마지막)
@ApiLogging
@Idempotent
@RateLimit
public ResponseEntity<?> method() { ... }

// ✅ 올바른 순서 (RateLimit가 먼저)
@RateLimit
@Idempotent
@ApiLogging
public ResponseEntity<?> method() { ... }
```

### 2. SpEL 표현식 주의
```java
// ❌ null 체크 없이 사용
keyExpression = "#authentication.principal.userId"

// ✅ null 체크와 함께 사용
keyExpression = "T(org.springframework.security.core.context.SecurityContextHolder).context.authentication?.principal?.userId ?: 'anonymous'"
```

### 3. 예외 타입 지정
```java
// ❌ 모든 예외에 재시도
@RetryOnFailure(retryOn = {Exception.class})

// ✅ 특정 예외만 재시도
@RetryOnFailure(
    retryOn = {RuntimeException.class},
    noRetryOn = {SecurityException.class, IllegalArgumentException.class}
)
```

## 🔧 성능 최적화

### 캐시 TTL 조정
```java
// 자주 변경되는 데이터: 짧은 TTL
@CacheResult(ttlSeconds = 30)

// 안정적인 데이터: 긴 TTL
@CacheResult(ttlSeconds = 3600)
```

### Rate Limiting 알고리즘 선택
```java
// 엄격한 제어: SLIDING_WINDOW
@RateLimit(algorithm = RateLimit.Algorithm.SLIDING_WINDOW)

// 버스트 허용: TOKEN_BUCKET
@RateLimit(algorithm = RateLimit.Algorithm.TOKEN_BUCKET)

// 간단한 제어: FIXED_WINDOW
@RateLimit(algorithm = RateLimit.Algorithm.FIXED_WINDOW)
```
