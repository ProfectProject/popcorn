## 🏗️ 주요 업무 가이드

### 1. 아키텍처 설계 및 검토

**시스템 아키텍처 검토 체크리스트**:
```yaml
Scalability:
  - [ ] 현재 트래픽 대비 여유 용량 확인
  - [ ] 오토스케일링 정책 적절성 검토
  - [ ] 데이터베이스 성능 병목 지점 분석
  - [ ] 캐시 전략 효율성 검토

Reliability:
  - [ ] 단일 장애점(SPOF) 식별 및 제거
  - [ ] 장애 복구 시간 목표 달성 여부
  - [ ] 백업 및 복구 전략 검증
  - [ ] 모니터링 커버리지 확인

Security:
  - [ ] 보안 정책 준수 여부 확인
  - [ ] 접근 제어 정책 검토
  - [ ] 데이터 암호화 상태 확인
  - [ ] 취약점 스캔 결과 검토

Cost Optimization:
  - [ ] 리소스 사용률 분석
  - [ ] Reserved Instance 최적화
  - [ ] 불필요한 리소스 식별
  - [ ] 비용 알림 임계값 설정
```

### 2. 팀 관리 및 협업

**팀 스탠드업 미팅 가이드**:
```yaml
Agenda (15분):
  1. 어제 완료한 작업 (각자 2분)
  2. 오늘 계획한 작업 (각자 1분)
  3. 블로커 및 도움 요청 (5분)
  4. 공지사항 및 우선순위 조정 (3분)

Follow-up Actions:
  - [ ] 블로커 해결 방안 논의
  - [ ] 리소스 재배치 필요성 검토
  - [ ] 외부 의존성 이슈 에스컬레이션
  - [ ] 다음 미팅 전 완료 목표 설정
```

**1:1 미팅 가이드**:
```yaml
주간 1:1 미팅 (30분):
  1. 개인 업무 진행 상황 (10분)
  2. 기술적 챌린지 및 지원 필요사항 (10분)
  3. 커리어 개발 및 교육 계획 (5분)
  4. 팀 프로세스 개선 아이디어 (5분)

Action Items:
  - [ ] 개인 목표 설정 및 추적
  - [ ] 교육 리소스 제공
  - [ ] 멘토링 또는 코칭 계획
  - [ ] 팀 프로세스 개선 실행
```

## 🚨 장애 대응 가이드

### 장애 대응 체크리스트
```yaml
Immediate Response (0-15분):
  - [ ] 장애 심각도 평가 (P0/P1/P2/P3)
  - [ ] 영향 범위 파악 (사용자, 서비스)
  - [ ] 초기 대응팀 구성
  - [ ] 커뮤니케이션 채널 개설

Investigation (15-60분):
  - [ ] 로그 및 메트릭 분석
  - [ ] 최근 변경사항 검토
  - [ ] 근본 원인 가설 수립
  - [ ] 임시 해결방안 검토

Resolution (1-4시간):
  - [ ] 해결방안 실행
  - [ ] 서비스 복구 확인
  - [ ] 사용자 영향 최소화
  - [ ] 모니터링 강화

Post-Incident (24-48시간):
  - [ ] 포스트모템 미팅 주최
  - [ ] 근본 원인 분석 완료
  - [ ] 개선 액션 아이템 정의
  - [ ] 문서화 및 공유
```

### 포스트모템 템플릿
```markdown
# 포스트모템: [장애 제목]

## 요약
- 발생일시: YYYY-MM-DD HH:MM
- 지속시간: XX분
- 영향범위: [서비스/사용자 수]
- 심각도: P0/P1/P2/P3

## 타임라인
- HH:MM - 장애 발생
- HH:MM - 감지 및 알림
- HH:MM - 대응 시작
- HH:MM - 임시 조치
- HH:MM - 완전 복구

## 근본 원인
[기술적 원인과 프로세스 원인]

## 영향 분석
[사용자, 비즈니스, 시스템에 미친 영향]

## 개선 액션
- [ ] 즉시 조치 (24시간 내)
- [ ] 단기 개선 (1주일 내)
- [ ] 중기 개선 (1개월 내)
- [ ] 장기 개선 (3개월 내)

## 교훈
[향후 유사 장애 방지를 위한 교훈]
```

## 🎯 성공을 위한 팁

1. **데이터 기반 의사결정**: 모든 결정을 메트릭과 데이터로 뒷받침
2. **투명한 커뮤니케이션**: 팀과 이해관계자에게 정기적으로 상황 공유
3. **지속적 학습**: 새로운 기술과 베스트 프랙티스 지속적 습득
4. **팀 임파워먼트**: 팀원들의 자율성과 책임감 증진
5. **고객 중심 사고**: 모든 결정이 최종 사용자에게 미치는 영향 고려

Platform Engineer로서 성공하기 위해서는 기술적 전문성뿐만 아니라 리더십, 커뮤니케이션, 전략적 사고가 모두 필요합니다. 이 가이드를 참고하여 효과적으로 팀을 이끌고 안정적인 플랫폼을 구축하시기 바랍니다.
